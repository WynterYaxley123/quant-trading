## 0. Headline

```
MAPPING_SOURCE_GAP
```

CNEquity **cannot supply the evidence an industry→ETF mapping requires**. It has no field, table, adapter or source label that links an ETF to its tracking index, and no field that links a Shenwan industry code to an ETF. The repo's own existing admission process independently reached the same conclusion from a different direction (`ETF_MAPPING_NOT_ADMISSIBLE`, 0/124 validated sectors).

**Therefore: `MANUAL_VERIFICATION_REQUIRED` for the mapping relation, and `MAPPING_SOURCE_GAP` for automated admission.** No mapping rows were generated by this audit.

---

## 1. The evidence hierarchy is fixed and must not be relaxed

The frozen product requirement defines a strict evidence priority, and forbids name-only admission:

| Priority | Evidence | Permitted to auto-admit? |
|---|---|---|
| 1 | **tracking index code exact** | Yes (if present and verified) |
| 2 | tracking index identity exact | Yes (if present and verified) |
| 3 | verified metadata relationship | Yes (if present and verified) |
| 4 | manual verified mapping | Yes, as a human act, with recorded provenance |
| 5 | **name-only match** | **Never** — explicitly forbidden for auto-admission |

CNEquity provides **none of priorities 1–3** for ETFs (§2), so the only lawful path is priority 4 plus a human-reviewed external evidence pack (§4).

## 2. Why CNEquity cannot supply priorities 1–3

### 2.1 `instruments` has no ETF-fund fields

`docs/datasets/schema.md:78-91` gives the complete `instruments` column set:

| Column | Type | Note |
|---|---|---|
| `symbol` | string | primary key |
| `name` | string | |
| `exchange` | string | `SH`/`SZ`/`BJ` |
| `asset_type` | string | `stock` / `etf` / `index` |
| `list_date` | date | nullable |
| `delist_date` | date | nullable |
| `prev_symbol` | string | nullable |
| `source` | string | provenance |
| `data_version` | string | provenance |
| `fetched_at` | timestamp | provenance |

**Absent from `instruments`:** tracking index code, tracking index name, fund type (行业/主题/宽基), fund company, management fee, fund size/AUM, inception/establishment date, share class, underlying basket. There is no separate fund-metadata dataset anywhere in the 42-dataset registry (`docs/datasets/catalog.md:3`).

**Consequence:** priorities 1 and 2 are structurally unavailable — the field does not exist, so no amount of fetching will populate it.

### 2.2 Classification systems are disjoint from ETF space

Shenwan membership is fetched by `src/cnequity/adapters/sw/industry_history.py` and its symbol normaliser **filters to A-share stock codes only** (`:80-85`):

```python
def _code_to_symbol(code: str) -> str | None:
    code = str(code).zfill(6)
    exchange = infer_exchange_from_code(code)
    if not is_all_a_symbol(code, exchange):
        return None
    return format_symbol(code, exchange)
```

`is_all_a_symbol` excludes ETF/LOF prefixes by construction, and the source file is a *stock* classification workbook (`StockClassifyUse_stock.xls`, `:33-35`). So `industry_members` describes stocks, never funds.

**Consequence:** there is no join key of the form *industry_code → etf_code* anywhere in the lake. Priority 3 is unavailable for the same structural reason.

### 2.3 The `industry_name` column is not a name map

`expand_sw_industry_as_of` writes (`:174`):

```python
# Official name map is a separate SW publish; code is stable for joins.
pl.col("industry_code").alias("industry_name"),
```

`industry_name` is an **alias of the numeric code**, not a resolved industry name. Any matching that compares `industry_name` to an ETF's name would be matching a number against a fund title — meaningless, and it would violate the name-only prohibition while appearing not to. Any future mapping must join on `industry_code` and resolve names from a separate, explicitly-cited SW publication.

### 2.4 The THS board taxonomy is a third, unrelated taxonomy

CNEquity's `sector_bars` uses 同花顺's own board codes: `881xxx` for 行业 (industry) and `885xxx` for 概念 (concept) (`src/cnequity/adapters/ths/boards.py:19`). Shenwan Level-2 codes are `801xxx`. These are **not** the same taxonomy and CNEquity ships no crosswalk between them. `sector_bars.board_type ∈ {industry, concept}` denotes *THS's* classification, not Shenwan's.

**Consequence:** even the board-bar dataset — the only industry-like series with full OHLC in the lake — cannot be joined to a Shenwan industry without an externally-sourced crosswalk that CNEquity does not provide.

The existing project already runs an ETF-mapping admission with a real official-evidence pack. `docs/data/shenwan_etf_mapping_admission.md:2-3` records:

> Status: **ETF_MAPPING_NOT_ADMISSIBLE**.

And `:32-38`:

|---|---:|---|
| VALIDATED | 0 | none |

| NOT_DIRECT_MAPPING | 15 | excluded |
| CONFLICT | 1 | excluded |

Key structural findings from that same document, which a CNEquity-based design must not contradict:

1. **Two evidence layers exist and only Layer 1 is provable.** `:25-28`: official documents prove **Layer 1** (ETF → currently disclosed tracking index) but do **not** prove **Layer 2** (tracking index → one specific Shenwan Level-2 sector). A matching product or index *name* is explicitly insufficient.
2. **Historical mapping dates are absent.** `:28-30`: `mapping_effective_from` and `mapping_effective_to` are both **0/22**. "An official listing date is not a mapping start date; a `CURRENT_RELATIONSHIP_ONLY` disclosure is not backfilled."
3. **Tracking-index code is only partial.** `:22-23`: tracking-index name complete 22/22, tracking-index **code** present only **11/22**.
4. **Broad-market ETFs cannot be promoted.** `:62-66`: `159915` has full official identity evidence and 3,589 local bars, yet is `NOT_DIRECT_MAPPING` and "cannot become a Shenwan Level-2 primary merely because local market data exists."
5. **The formal mapping is 124 explicit `UNKNOWN` rows: 0/124 validated (0%)**, with candidate diagnostic coverage 6/124 (4.84%) labelled `CANDIDATE ONLY; NOT ADMITTED FOR BACKTEST` (`:72-77`).

This corroborates §2 from the empirical side: the blocker is not effort, it is that **the required relation is not published in a machine-readable, historically-dated form by any source in scope.**

## 4. Required contract fields (target schema — NOT populated by this audit)

The frozen requirement specifies the output contract fields. The existing repo type `MappingEvidence` (`strategies/sw_sector_rotation/src/portfolio/sector_etf_mapping.py:65-87`) already realises almost exactly this shape and is the correct anchor:

| Required field | Existing `MappingEvidence` attribute | Source that must fill it |
|---|---|---|
| `industry_code` | `sector_code` | CNEquity `industry_members.industry_code` (`classification_system="sw"`) |
| `industry_name` | `sector_name` | **external SW name publish** (not CNEquity; see §2.3) |
| `etf_code` | `etf_code` | CNEquity `instruments.symbol` where `asset_type='etf'` |
| `etf_name` | `etf_name` | CNEquity `instruments.name` |
| `tracking_index_code` | `tracking_index_code` | **external official fund document** (not CNEquity) |
| `tracking_index_name` | `tracking_index_name` | **external official fund document** (not CNEquity) |
| `mapping_method` | `evidence_type` | human-declared evidence class |
| `source` | `source_provider` / `source_url` / `source_file` | provenance |
| `effective_from` | `mapping_effective_from` | **external evidence; 0/22 today** |
| `effective_to` | `mapping_effective_to` | **external evidence; 0/22 today** |
| `verified_at` | `source_retrieved_at` | retrieval timestamp |
| `mapping_confidence` | `mapping_status` (`VALIDATED`/`PARTIAL_EVIDENCE`/…) | evaluator verdict |
| `admission_status` | `mapping_admission(...)` return | `ETF_MAPPING_READY` / `_PARTIAL` / `_NOT_ADMISSIBLE` |

Additional evidence-integrity fields already enforced and to be retained: `source_sha256` (mandatory whenever `source_file` is set), `etf_listing_date`, `market` (must equal the `etf_code` prefix), `is_primary`.

### 4.1 Enforced invariants (existing guards, must be preserved)

From `validate_mapping_evidence` (`sector_etf_mapping.py:98-153`):

- A `VALIDATED` row must carry **all** of `etf_code, etf_name, market, tracking_index_code, tracking_index_name, mapping_effective_from, etf_listing_date, source_provider, source_retrieved_at, evidence_type`, plus a `source_url` or `source_file` (`:123-131`).
- Only `VALIDATED` rows may be `is_primary` (`:121-122`).
- ETF codes must carry a market prefix matching `(sh|sz)\d{6}` and `market == etf_code[:2]` (`:110-111`, `:132-133`).
- A local source file without `source_sha256` is rejected (`:119-120`).
- Multiple candidates without an explicit `MULTIPLE_CANDIDATES` label is rejected (`:150-153`).
- **The mapping must contain an explicit `UNKNOWN` row for every sector** — "不能用空表暗示全覆盖" (`:103`, `:138-139`). A short table can never masquerade as full coverage.
- Two `primary` rows overlapping in time for one sector is rejected (`:140-149`).

These guards are the mechanism by which the name-only prohibition is made operational: a name match cannot satisfy them.

## 5. Admission gate semantics

`mapping_admission` (`sector_etf_mapping.py:208-219`):

```
mapped = {r.sector_code for r in rows if r.mapping_status == "VALIDATED" and r.is_primary}
if not mapped or not executable_counts:            → ETF_MAPPING_NOT_ADMISSIBLE
if len(mapped) == len(catalog) and min(executable_counts) >= 5:
                                                   → ETF_MAPPING_READY
otherwise                                          → ETF_MAPPING_PARTIAL
```

Read with the current inputs (`mapped` empty, `executable_counts` all zero), this returns **`ETF_MAPPING_NOT_ADMISSIBLE`** — matching `docs/data/shenwan_etf_mapping_admission.md:2`.

Note the gate is **conservative by design**: "missing evidence never becomes READY." `ETF_MAPPING_READY` additionally requires every sector mapped *and* at least 5 executable ETFs on the limiting date — a portfolio-level tradability condition, not just a mapping condition.

### 5.1 Per-date executability is separate from mapping validity

`daily_mapping_availability` (`:173-205`) resolves the mapping **twice** — once at the signal session and once at the execution session — and requires them to agree (`:185-187`), then computes:

```
is_etf_executable = is_mapping_active AND is_listed AND is_tradable
is_executable     = sector_bar_valid AND is_etf_executable
```

with `execution_date > signal_date` enforced (`:180-181`), and a bar rejected unless `bar["date"] == execution_date` **and** `bar["etf_code"] == r.etf_code` (`:190-194`). `valid_daily_open` (`src/data/providers/etf_local.py:18-28`) additionally requires finite, strictly positive OHLC **and** `high >= max(open, low, close)` and `low <= min(open, high, close)`.

This is the correct T-close-signal → T+1-open-execution shape and must be retained verbatim.

## 6. Multiple ETFs per industry — 20-day liquidity selection

**Requirement:** if one industry has several admitted ETFs, choose the one with the largest average `amount` over the last 20 trading days.

### 6.1 Can CNEquity compute it?

| Prerequisite | CNEquity capability | Verdict |
|---|---|---|
| Daily ETF `amount` | `daily_bars.amount`, unit `CNY`, present for ETF/LOF rows — **provided the ETF is in the ingest scope** | Conditional |
| 20 exchange sessions | `trading_calendar` (`(trade_date)`, primary `tdx_protocol`, backup `exchange`) | **Available** |
| ETF OHLC for execution | `daily_bars` | Conditional (see §6.2) |

So the **computation is feasible**, but only after two ingestion preconditions are satisfied — and neither is satisfied by default.

### 6.2 Precondition 1 — ETF bars are NOT ingested by default

`docs/getting-started/configuration.md:155` sets `[universe].ingest` default to `all_a`. `:161-163` gives the values: `all_a` (沪深北 A 股), `all_a_sh_sz`, `all_instruments` ("instruments 列出的全部代码，含 ETF/LOF 行情代码").

`:167-170` explains why the default excludes ETFs:

> `instruments` 会返回 TDX 列出的全部代码，其中约四分之一是 ETF/LOF/基金行情代码：没有任何研究口径会选中它们，也没有哪个已配置的源能稳定提供它们。把它们放进日更会占掉四分之一的抓取量，用没人需要的代码触发东财和新浪的熔断，并把填不上的 `symbol×session` 键留给覆盖门禁 —— 门禁随后拒绝为当天落盘。

Translation of the operative risk: putting ETF/LOF codes into the daily run consumes ~25% of the fetch budget, trips EastMoney and Sina circuit breakers for codes nobody was querying, and leaves unfillable `symbol×session` keys that make the **coverage gate reject the entire day's write**.

**Consequence:** with the default configuration, ETF `daily_bars` are absent, so the 20-day average-amount rule **has no input**. Selecting a dedicated ETF ingest scope is a required, deliberate configuration change with a documented cost — not a default.

### 6.3 Precondition 2 — all four universe profiles exclude ETFs

Every registered research profile has `include_etf=False` (`src/cnequity/domain/universe_profiles.py`):

| Profile | `include_etf` | `research_eligible` |
|---|---|---|
| `cn_a_sh_sz_research_v1` | **False** (`:177`) | True |
| `cn_a_all_experimental_v1` | **False** (`:205`) | False |
| `legacy_all_a` | **False** (`:233`) | True |
| `legacy_all_a_sh_sz` | **False** (`:254`) | False |

`cn_a_sh_sz_research_v1`'s description is explicit: "Beijing, CDR and ETF/LOF instruments are outside scope" (`:170-173`).

**Consequence:** there is **no ETF universe profile**. ETF bars must be read via explicit `symbols=[...]` selection (`load(..., symbols=[...])`), not via `universe=`. Any ETF selection logic must therefore build and persist its own symbol set and must not claim profile-governed scope. Defining an ETF profile would be a code change — **out of scope for this audit**.

**The block is enforced in three independent places**, so it cannot be worked around by naming a different universe:

| Layer | Evidence |
|---|---|
| Query layer | `query/universe.py:37` `SUPPORTED_UNIVERSES = frozenset({"all_a","all_a_sh_sz"})`; `:44-49` raises otherwise. ETF prefixes are **actively excluded** by `_all_a_symbol_expr` (`:60-64`), applied at `:311` and `:379-388`. |
| Profile registry | All four profiles `include_etf=False`; `resolve_universe_profile` accepts only those four names (`domain/universe_profiles.py:275-289`), and `legacy_universe` is constrained to `{"all_a","all_a_sh_sz"}` (`:80-83`) — so **an ETF profile cannot even be constructed**. |
| MCP / CLI surface | `mcp_server/tools.py:347-348` rejects any other universe; `mcp_server/catalog.py:116-121` publishes the same enum. |

> **Note (doc drift):** `include_etf` is declared (`domain/universe_profiles.py:66`) and serialized (`:106`),
> but **no code ever reads it**. The exclusion is enforced by the query layer's prefix filter, not by the
> profile flag. The flag is currently inert — a reader who believes it is the control would be wrong.

### 6.4 Edge cases the selection rule must handle

The frozen requirement names these explicitly. Each is a real hazard in this lake:

| Case | CNEquity behaviour | Required handling |
|---|---|---|
| **Newly listed ETF** | `instruments.list_date` present; bars start later | **Reject from ranking** until it has a full 20-session window. Do not rank on a partial window — it would favour a brand-new fund arbitrarily. |
| **Insufficient history** | Fewer than 20 bars available | Reject; do **not** substitute a shorter window (that is a silent methodology change). |
| **Missing sessions** | Row simply absent (the source publishes no bar); interior gaps are visible to the dense-coverage watermark | Do not interpolate. Require 20 **exchange sessions from `trading_calendar`** to be covered, not 20 mere rows. |
| **Suspension** | `trading_status.status='suspended'`; the row may still carry carried-forward OHLC with `volume=0, amount=0` (`docs/datasets/schema.md:13`) | Treat `amount=0` rows as **non-trading**. A suspended ETF must not win a liquidity contest by having its stale amount averaged in, nor be treated as having traded. |
| **`amount = 0`** | Possible on suspension or a degenerate feed | Exclude from the average, and if fewer than 20 genuine sessions remain, reject the ETF. |
| **Degenerate feed values** | CNEquity already guards this pattern: `_MIN_TRADED_AMOUNT = 1.0` with the comment "Below one yuan a 'turnover' is a feed artefact, not a trade" (`src/cnequity/derive/industry_index.py:46-47`), because a whole-universe feed once delivered `amount ≈ 5.9e-39` (`:212-222`) | Apply an equivalent floor. A sub-yuan "turnover" must not be averaged as money. |
| **`NaN`** | `industry_index` explicitly nulls a weighted average over no weights: "a weighted average over no weights is not zero" (`src/cnequity/derive/industry_index.py:289-294`) | Follow the same rule: insufficient data yields **null**, never 0. |
| **Duplicate rows** | Compact dedupes by primary key keeping the max `fetched_at` (`docs/datasets/schema.md:860-862`); primary key is `(symbol, trade_date)` | Rely on the dataset contract; do not add a second dedupe that could mask a contract violation. |
| **Rename** | `instruments.prev_symbol` exists (`docs/datasets/schema.md:88`) | Follow `prev_symbol` for identity continuity; never treat a rename as a delisting + new listing. |
| **Delisted / inactive** | `instruments.delist_date`; `trading_status.status='delisted'`, `is_trading=false`, `source='derived_delisted'` (`docs/datasets/sources.md:51`) | Exclude from ranking **and** from the admitted set. Note CNEquity deliberately does not backfill historical `delisted` rows: "某一天的状态是当时观测到的事实，用今天的退市日期倒填会凭空造出当时并不存在的 point-in-time 事实" (`docs/datasets/schema.md:135-136`). |
| **ETF → index identity** | `asset_type='etf'` distinguishes funds from stocks and indices | Never admit an `asset_type='index'` row as tradable. |

### 6.5 Verdict on 20-day liquidity selection

```
20d liquidity selection feasibility: FEASIBLE ONLY AFTER EXPLICIT CONFIGURATION
```

Feasible in principle — `daily_bars.amount` (CNY) plus `trading_calendar` supply exactly the needed inputs, and the average-amount rule is well-defined once suspension and degenerate-amount rows are excluded. **But it is not feASIBLE out of the box**: ETF bars are excluded by `[universe].ingest = "all_a"` and by all four universe profiles, and enabling ETF ingest carries the documented costs in §6.2. This audit does **not** enable it and does **not** generate a production mapping.

## 8. What CNEquity *can* contribute to the mapping pipeline

CNEquity is not useless here — it cleanly supplies the **instrument and market-data side** of the mapping, once configured:

| Contribution | CNEquity source | Status |
|---|---|---|
| ETF universe enumeration | `instruments` where `asset_type='etf'` | Available (note: ~25% of `instruments` rows are fund quote codes, `configuration.md:167`) |
| ETF code / name / exchange | `instruments.symbol` / `.name` / `.exchange` | Available |
| ETF listing date | `instruments.list_date` | Available, **nullable**; TDX writes `None` and EastMoney's ETF-board `clist` (`f26`) fills only symbols already present in the TDX frame (`adapters/eastmoney/instruments.py:67,103-105`) |
| ETF delisting status | `instruments.delist_date` + `trading_status` | Available with caveats — see §8.1 |
| ETF daily OHLC | `daily_bars` | **Conditional** on ingest scope |
| ETF amount (liquidity) | `daily_bars.amount`, unit CNY | **Conditional**, and **null on the Sina route** — see §8.2 |
| ETF adjustment factors | `adj_factors` — ETFs are explicit first-class (`derive/adj_factors.py:437-456`, filter `asset_type ∈ {stock, etf}`); stocks read Sina field `f`, ETF/LOF read `s` (`adapters/sina/adj_factors.py:50-55,137-144`) | Available |
| Shenwan industry PIT membership | `industry_members` (`classification_system='sw'`) | Available, reconstructed monthly from 2020 |
| Trading calendar | `trading_calendar` | Available |

### 8.1 ETF `risk_warning` is asserted `False` by construction — a real trap

`trading_status` **can** carry ETF rows, ETF suspensions and ETF delistings, but with one dangerous
asymmetry:

- **EastMoney board path cannot mark an ETF halted.** Its suspension set filters through
  `is_all_a_symbol` (`adapters/eastmoney/trading_status.py:128`), so an ETF can never appear in it;
  `is_trading` is therefore **always `True`** for ETFs on this path (`:158-159`).
- **`risk_warning` is written as `False` for SH/SZ ETFs** because the ST set is also built with the
  `is_all_a_symbol` resolver (`:83`, `:160`) and so never contains an ETF.

**Consequence:** an SH/SZ ETF row can read `is_trading=true, risk_warning=false` — an *asserted clean*
status — from a board that structurally cannot contain ETFs. This is the same defect class the code
documents for Beijing, where the resolution was to write **null** rather than a false negative
(`adapters/eastmoney/trading_status.py:17-23`). Consumers must **not** treat ETF `risk_warning=False` as
evidence.

Paths that *do* cover ETFs correctly:

| Path | Evidence |
|---|---|
| Exchange whole-board quotes (ETF halts observable) | `adapters/exchange/trading_status.py:169-196`; `_keep_symbol` = `is_all_a_symbol or is_etf_symbol` (`adapters/exchange/daily_quotes.py:131-133`) |
| Derived bar-gap suspensions (asset-agnostic) | `derive/trading_status_history.py:41-139`, written `:166-173` — but an ETF **with no `daily_bars`** (the default scope) gets no derived rows either |
| Delisted rows (no asset filter) | `steps/reference.py:404-440`, `:496-519` |

### 8.2 `amount` can be null on ETF rows — the liquidity ranker must handle it

`daily_bars.amount` is **nullable by contract**: it is not in
`_CORE_BAR_REQUIRED_COLUMNS["daily_bars"] = ("open","high","low","close","volume")`
(`domain/schemas.py:764-769`). Per-source behaviour:

| Source | `amount` on ETF rows | Evidence |
|---|---|---|
| `tdx_protocol` (primary) | **Always present** — rows with null amount are dropped | `adapters/tdx_protocol/bars.py:96-99` |
| `ths` (deep history) | Present | `adapters/ths/stock_bars.py:70` |
| `exchange` (SSE/SZSE) | Present; ETF rows admitted | `adapters/exchange/daily_quotes.py:229,302` |
| **`sina`** | **Always NULL** — explicitly not invented | `adapters/sina/bars.py:283-285` ("leave it null rather than inventing close × volume") |
| `eastmoney` clist tip | **ETF rows cannot exist** (resolver drops them) | `adapters/eastmoney/bars.py:74-77` |
| `eastmoney` per-symbol kline | Nullable | `adapters/eastmoney/bars.py:215,229-232` |

An SH/SZ ETF normally gets TDX (amount present) but **can** land on the Sina gap-fill leg
(`steps/bars.py:3277-3285`) and then store `amount = NULL`. A naive `sort by amount` silently drops those
rows from the 20-day liquidity contest — which is a *silent admission decision*, exactly what §6.4 forbids.

The lake labels but does not fix this: `quality/unit_checks.py:254-329`
(`daily_bars_amount_completeness_findings`) groups by source, marks `sina` as `source_limited=True`, and
emits `severity="info"` — and it is **not asset-type aware**, so ETF-specific null rates are not reported
separately.

**Required handling:** treat null `amount` as *insufficient evidence*, exclude the ETF for that session,
and never substitute `close × volume` (`adapters/sina/bars.py:283-285` rejects that inference for good
reason).

**The gap is exactly one thing: the fund→index→industry relation.** CNEquity supplies both endpoints of a mapping it cannot itself justify.

## 9. Hard blockers recorded

```
MAPPING_SOURCE_GAP

  - `[universe].ingest` defaults to `all_a`, excluding ETF/LOF bars; enabling ETF ingest has documented
    fetch-budget and coverage-gate consequences.
```
