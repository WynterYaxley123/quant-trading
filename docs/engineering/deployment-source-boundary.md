# Deployment source boundary

## Source authority

The GitHub repository is the `SOURCE_OF_TRUTH_REPOSITORY`; a local deployment root
is `LOCAL_DEPLOYMENT_ROOT`. The maintainer reference root `D:\QuantForge` is not a
public prerequisite. It contains factual data, private evidence, frozen operational
state, external pinned dependencies and a live deployment checkout.

A recursive local inventory classified 29,503 candidate source/config/document
files. Static content review covered 1,632 owned script/document files without
executing them. Third-party source and installed dependencies were checked by
identity/boundary, not copied. Market records, secrets and sealed research payloads
were classified by their protected boundary without opening their values. The full
machine-specific inventory remains local and is not published in this repository.

## Decisions and reusable assets

| Local asset or category | Canonical disposition |
| --- | --- |
| Local root README | Public source/state boundary in bilingual READMEs, deployment and operations guides; local note remains local |
| Host-port repair record | Read-only reservation/listener diagnostic and host-publication knowledge; no machine history copied |
| Live host-port override | Parameterized example, retaining the effective local override because Compose references it |
| Exact external CNEquity identity | Small upstream/version/commit/interface/license metadata; no vendoring |
| Snapshot/root diagnostics | Read-only source/state boundary verifier, replacing machine paths with external config |
| Live operations checkout | Already versioned canonical runner, scheduler, launcher and integrity code; retain deployment copy |
| Global DNS/locale reset and remote-control installer | No reusable project contract; do not execute or migrate |
| Desktop/window capture scripts | Unrelated local user diagnostics; do not publish or silently delete |
| Provider backfills, research record builders and old acceptance scripts | Keep historical local provenance; no model/data/state migration |
| Runtime, factual lake, backups, receipts and private evidence | Local-only protected state |

The new verifier is standard-library-only, has help, strict config/path validation,
resolved containment, disjoint roots, fixed provider identity and sanitized output.
It never opens business payloads or writes state. The host-port tool uses argv-only
Windows read commands and supports localized range headers and IPv6 reservations.
It cannot change DNS, locale, services, mappings or accounts.

## Invariants and integrity

V1 model/economic semantics, V2 frozen candidate, factors, horizons, training windows,
fusion, mapping policy, releases and scientific overlay stay byte-identical.
Final OOS is not reopened or retuned. There is no new broker/order path.
The active source manifest is a new delta; historical V8 and earlier certificates
remain immutable. The generator hashes the superseded delta as a source record,
and the active verifiers use the new manifest identity. Only certificate selection
changes in strategy/API infrastructure; no quantitative behavior changes.

## Regression evidence

The regression gates cover synthetic deployment containment, symlink escape,
provider drift/dirty source, forbidden execution flags and byte-preserved account
sentinels; Windows port parsing and fail-closed command adapters; existing runner,
scheduler, publication/crash, API and frontend suites. Documentation mapping/link
checks, Ruff, staged typing, pre-commit, implementation verification and repository
source/history security auditing remain required.

Fresh-clone acceptance builds the pinned independent image, runs the minimal demo
and portable tests without external market/runtime mounts. Deployment acceptance is
read-only: scheduler definition, container/image/mount identities, provider pin and
runtime/data file inventory are compared before/after. No formal one-shot, signal,
intent or fill is used for verification. Deployment references remain unchanged.

Runtime initialization and private framework/provider acceptance are outside the
portable tier. A skip or absent private fixture is not counted as a passing result.
The public scientific confidence limitations and existing dependency/typing debt
remain visible; this consolidation does not change them.

Local acceptance: portable Python 1,273 passed, 2 skipped, 99 deselected; Linux Node
API/security/operations/launcher suites 145 passed, 5 Windows-only skips. Windows
launcher/scheduler/operations acceptance passed all 9 tests. Research API had 63
passing synthetic tests and 7 private integration skips. Dashboard tests, typecheck,
lint and build passed, with private artifacts kept outside the test environment.
Ruff, staged typing (168 existing legacy diagnostics; touched/new modules zero),
pre-commit, references and source/history security auditing passed. Local boundary
verification and scheduler preflight returned no runner invocation/business events.
Scheduler dry-run records only a diagnostic log receipt; no account state changes.
